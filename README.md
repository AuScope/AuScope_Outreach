# AuScope Outreach: AuSIS Map

Interactive map of **AuSIS** (Australian Seismometers In Schools, FDSN network
code **S1**, DOI `10.7914/SN/S1`). Built as a single self-contained HTML file
(vanilla JS + Leaflet 1.9.4, no build step) and served from GitHub Pages,
embedded via iframe at <https://www.auscope.org.au/ausis>.

---

## What's in this feature

| Path | Purpose |
|---|---|
| `AuSIS_Map.html` | The map. Self-contained; open it directly or via Pages. |
| `scripts/render_waveforms.py` | Hourly: renders last-hour waveform PNGs. |
| `scripts/update_quakes.py` | Hourly: builds the rolling earthquake store. |
| `scripts/render_event_waveforms.py` | Per-event: renders earthquake "record sections". |
| `scripts/requirements.txt` | Pinned Python deps (shared by all three scripts). |
| `.github/workflows/waveforms.yml` | Schedules the last-hour waveform render. |
| `.github/workflows/quakes.yml` | Schedules the earthquake-store update. |
| `.github/workflows/event_waveforms.yml` | Schedules the event record-section render. |
| `data/earthquakes_24mo.geojson` | Generated by the quake job, committed to `main`. |

The map also reads `data/ausis_stations.geojson` and `data/ausis_status.json`
if present and falls back to live IRIS FDSN station metadata otherwise.

There are **three generated outputs**, each from its own pipeline:

* the force-pushed flat `waveforms` branch (last-hour station PNGs),
* `data/earthquakes_24mo.geojson` on `main` (earthquake catalogue),
* the force-pushed flat `event-waveforms` branch (per-earthquake record sections).

## The map

* **Stations** come from the IRIS FDSN station service (network S1), with a
  local `data/ausis_stations.geojson` fallback so the map still draws if the
  live service is unreachable. Colour encodes status (streaming / intermittent
  / decommissioned).
* **Fullscreen button** — top-right of the map. It uses the browser Fullscreen
  API where the embedding page permits it (`allow="fullscreen"` on the iframe)
  and otherwise opens the map standalone in a new tab, so it is never a dead
  control inside a cross-origin iframe.
* **Station waveform popup** — clicking a streaming station shows the last hour
  of *ground velocity* (instrument response removed, µm/s) as a pre-rendered
  PNG, with a **Raw / Local / Distant** segmented switch:
  * **Raw** — response-removed velocity, no filter.
  * **Local** — 1 Hz high-pass, emphasises nearby earthquakes.
  * **Distant** — 0.02–0.1 Hz band-pass, emphasises distant teleseisms (often
    near-flat unless a large distant quake occurred — that is expected).
* **Earthquakes layer** — toggled from the on-map toolbar. A time-window
  selector (24 h / 7 d / 30 d / 24 mo, default **7 d**) filters the displayed
  events client-side. Clicking a quake draws dashed lines to the nearest 3
  streaming stations.
* **Earthquake popup** — magnitude, place, time, depth, coordinates. If a
  **record section** has been rendered for that event it is shown here (see
  Pipeline 3); otherwise the popup lists the nearest 3 AuSIS stations instead.
  The nearest-station list is deliberately shown **only when there is no record
  section** (the section already names the stations), so remote / small /
  capped quakes still get AuSIS context while showcase events get the plot.

Everything the browser loads is **same-origin** (the waveform/section PNGs are
images, which are not subject to CORS; the quake store is a committed file).
The browser never calls EarthScope, GA, or AusPass directly.

## Pipeline 1 — last-hour waveforms (`waveforms.yml` + `render_waveforms.py`)

Runs hourly (`cron: "0 * * * *"`; for a rolling "last hour" plot).

1. Two bulk FDSN requests to **EarthScope** for the whole S1 network: one for
   the last hour of `?HZ` waveforms, one for station responses.
2. Per station: pick the best vertical channel (BHZ > HHZ > EHZ > SHZ), remove
   the instrument response → µm/s, render three PNGs (`<CODE>_raw.png`,
   `<CODE>_local.png`, `<CODE>_distant.png`) plus `manifest.json`.
3. `out/` is published to a **force-pushed orphan `waveforms` branch** — a
   single fresh commit each run, so history never accumulates and the repo
   footprint stays flat (~3 MB) forever.

The map reads the PNGs from
`https://raw.githubusercontent.com/<owner>/<repo>/waveforms/<CODE>_<variant>.png`.

**This requires the repository to be public**.

If a station's response metadata is missing for the hour it is skipped (logged
as `skipped`) rather than plotted in the wrong units. If EarthScope returns no
data the run fails loudly so it is visible in the Actions log; the previous
`waveforms` branch is left intact.

## Pipeline 2 — earthquake store (`quakes.yml` + `update_quakes.py`)

Runs hourly at `cron: "20 * * * *"` (offset from the waveform job).

1. Fetches Geoscience Australia's pre-built feed
   `https://earthquakes.ga.gov.au/cache/recent-earthquakes.json` (a rolling
   ~7-day GeoJSON FeatureCollection), sending a browser-like `User-Agent` and
   `Referer: https://earthquakes.ga.gov.au/` so CloudFront does not 403 it.
2. Normalises each event to a small shape and **merges by `event_id`** into
   `data/earthquakes_24mo.geojson`, keeping the most-recently-modified version
   of each quake (GA revises magnitude / depth / review status over time).
3. Prunes anything older than 730 days, then commits the file to `main`
   **only if it changed**.

Region/magnitude policy: keep all events located in Australia, plus global
events of magnitude ≥ 4.5 (so large teleseisms AuSIS stations actually record
still appear). If GA fails **and** there is no existing store, USGS FDSN is
used once as a seed so the map is never empty; otherwise a failed GA hour
simply leaves the store untouched for the next run (the job never hard-fails).

> The GA `cache/recent-earthquakes.json` feed is undocumented (though stable in
> practice). If its path or shape changes, the job degrades safely (keeps the
> last good store; the change is visible in the Actions log) rather than breaking
> the live map.

The store accumulates from the first successful run forward — it does not
back-fill history, so the 24-month view fills out over time. This adds ~1
commit/hour to `main` (tiny text diffs); squash periodically if desired.

## Pipeline 3 — event record sections (`event_waveforms.yml` + `render_event_waveforms.py`)

Runs every 3 hours at `cron: "40 */3 * * *"`. Produces one composite "record
section" PNG per qualifying earthquake: the event's ground motion at the
nearest AuSIS stations, stacked nearest-to-furthest on a shared time axis so
the wavefront is visibly later at more distant stations — the "watch the wave
travel" teaching artefact.

Selection from `data/earthquakes_24mo.geojson`:

* Australian region — GA's in-Australia flag, or within a generous
  continental + near-coast bounding box (a pragmatic stand-in for a true
  200 km-from-coastline buffer; combined with GA's regional focus it captures
  onshore and near-offshore events without shipping a coastline dataset).
* Magnitude ≥ **3.0**.
* Origin age between `MIN_AGE_HOURS` and `MAX_AGE_DAYS`. The lower bound is a
  **deliberate data-latency delay**.

Per qualifying event:

* The 10 nearest streaming stations within **1500 km** are candidates (a
  station further than that would not show a clear regional arrival anyway;
  for remote events with no station inside the cap, no section is produced —
  expected, not a failure).
* One bulk FDSN request for the 30-minute window (origin − 5 min →
  origin + 25 min), identical across all stations so the time axis is shared.
* Keep the 5 closest that returned usable data (implicit fall-through to
  further stations); skip the event if fewer than `MIN_TRACES` (2) have data.
* Response removed → µm/s, 1 Hz high-pass (the filter that makes a regional
  arrival visible). Each lane is labelled with the **school name** (from FDSN
  site metadata, prominent) with the station code small beneath it and the
  distance below; if metadata has no usable name the lane falls back to the
  station code alone.

**Render-once:** a `manifest.json` on the `event-waveforms` branch lists
already-rendered event ids. Each run only fetches/renders genuinely new
qualifying events; aged-out events are pruned; **GA revisions are not chased**
(an event is rendered once on first qualifying sighting). Steady state does
almost no work. Published to a **force-pushed flat `event-waveforms` branch**,
same flat-history design as Pipeline 1.

> No signal-quality QC is applied: a lane is included if it returned data, even
> if that data is flat/dead/gappy. A junk lane can therefore appear in a
> section. This was a deliberate scope decision; if showcase quality suffers,
> revisit adding completeness / not-flat / not-clipped / sane-amplitude gates.

### Testing vs production config

`render_event_waveforms.py` ships with **testing** values so you can validate
against recent events without waiting a day:

| | Testing (shipped) | Production (before going live) |
|---|---|---|
| `MIN_AGE_HOURS` | `1` | `24` |
| `MAX_AGE_DAYS` | `3` | `14` |

At a 1 h floor expect many events to be skipped for missing data — that is
data latency, not a bug. Bump `MIN_AGE_HOURS` to ~6–12 during testing if too
few events have complete data to judge the renderer. Switching to production
is a two-number edit, clearly commented in the script.

## Deploying / running

GitHub Pages serves the AuSIS map from `main`. To make changes live, edit
`AuSIS_Map.html` on `main`. All three workflows have `workflow_dispatch`, so
they can be run manually from the Actions tab.

First-time setup in a new repo:

1. Ensure the repository is **public** (see the Pipeline 1 note).
2. Set **`WAVEFORM_REPO`** in `AuSIS_Map.html` (top of the `<script>` block)
   to the exact `owner/repo` as it appears in the GitHub URL. This is
   **case-sensitive** on raw.githubusercontent.com and is the only hardcoded
   repo reference — the workflows use `${{ github.repository }}` and adapt
   automatically.
3. Run **Hourly AuSIS waveforms** manually. Expect `EARTHSCOPE: N traces +
   response metadata OK` and per-station `OK (BHZ) — raw, local, distant`.
   Creates the `waveforms` branch.
4. Run **Hourly earthquake store** manually. Expect `GA: N events fetched`
   and `Merged: +N new …`, then a commit of `data/earthquakes_24mo.geojson`.
   Until this runs the earthquake layer is simply empty (handled gracefully).
5. Run **Event waveform sections** manually (needs the quake store from step 4
   and `scripts/requirements.txt`). Expect `N event(s) qualify` then per-event
   `rendered (K stations)` or a skip reason. Creates the `event-waveforms`
   branch. A high skip rate at the testing 1 h floor is expected.
6. Load the map and confirm: stations show waveforms with the
   Raw/Local/Distant switch; the earthquake toolbar toggle and window selector
   work; a rendered event's quake popup shows its record section; the
   fullscreen button works (true fullscreen if the iframe allows it, else a
   new tab).

## Configuration reference

`AuSIS_Map.html` (top of `<script>`):

| Constant | Default | Meaning |
|---|---|---|
| `WAVEFORM_REPO` | `AuScope/AuScope_Outreach` | **Verify** — exact owner/repo, case-sensitive. |
| `WAVEFORM_BRANCH` | `waveforms` | Orphan branch holding last-hour PNGs. |
| `EVENT_WF_BRANCH` | `event-waveforms` | Orphan branch holding record sections. |
| `WAVEFORM_NEAR_LINKS` | `3` | Nearest stations the dashed lines connect. |
| `WAVEFORM_NEAR_LIST` | `3` | Nearest stations listed when no section exists. |
| `QUAKE_STORE` | `data/earthquakes_24mo.geojson` | Same-origin quake store path. |
| `quakeWindowDays` | `7` | Default earthquake display window (days). |

`scripts/render_waveforms.py`: `DATA_CENTRES`, `CHANNEL_PREF`, `LOCAL_HP_HZ`,
`DISTANT_BP_HZ`, `WINDOW_MINUTES`.

`scripts/update_quakes.py`: `RETENTION_DAYS` (730), `GLOBAL_MIN_MAG` (4.5),
`GA_URL`, `STORE_PATH`.

`scripts/render_event_waveforms.py`: `MIN_AGE_HOURS` / `MAX_AGE_DAYS` 
(production 1 / 14), `MIN_MAG` (3.0), `MAX_DIST_KM` (1500),
`N_CANDIDATES` (10), `N_KEEP` (5), `MIN_TRACES` (2), `PRE_MIN` / `POST_MIN`
(5 / 25), `LOCAL_HP_HZ`, `AU_BBOX`.
